# macOS CoreBluetooth Implementation Guidelines (Sprint 1)

This document provides guidelines for implementing the macOS companion application using the CoreBluetooth and CryptoKit frameworks, enabling successful pairing with the Android application without modifying Android code.

---

## 1. BLE Advertising Setup (CBPeripheralManager)

Since CoreBluetooth does not expose the macOS device's physical BLE MAC address, macOS must advertise its identity to allow Android to discover it.

### Setup Steps:
1. Initialize a `CBPeripheralManager` instance.
2. Formulate the advertising dictionary:
   * `CBAdvertisementDataServiceUUIDsKey`: An array containing `CBUUID(string: "4F101A2B-3C4D-5E6F-7A8B-9C0D1E2F3A4B")` (Continuity Service UUID).
   * `CBAdvertisementDataManufacturerDataKey`: A `Data` payload containing:
     * First 2 bytes: `0xFFFF` (Custom test manufacturer identifier in little-endian / big-endian).
     * Next 16 bytes: The raw 128-bit bytes of your stable macOS `advertisingIdentifier` UUID.
3. Call `peripheralManager.startAdvertising([:])` passing the configured dictionary.

---

## 2. GATT Database Setup (macOS Server)

macOS must publish the GATT Service and characteristics, adding them to the `CBPeripheralManager`:

```swift
let service = CBMutableService(type: CBUUID(string: "4F101A2B-3C4D-5E6F-7A8B-9C0D1E2F3A4B"), primary: true)

let writeChar = CBMutableCharacteristic(
    type: CBUUID(string: "4F101A2C-3C4D-5E6F-7A8B-9C0D1E2F3A4B"),
    properties: [.write, .writeWithoutResponse],
    value: nil,
    permissions: [.writeable]
)

let notifyChar = CBMutableCharacteristic(
    type: CBUUID(string: "4F101A2D-3C4D-5E6F-7A8B-9C0D1E2F3A4B"),
    properties: [.notify],
    value: nil,
    permissions: [.readable]
)

service.characteristics = [writeChar, notifyChar]
peripheralManager.add(service)
```

## 3. Handling Long Characteristic Writes (Long Writes)

Android requests an MTU size of 512 bytes on connection. However, if a lower MTU size is negotiated, Android payloads may exceed the MTU size. 

### macOS Handler Requirements:
* macOS must implement `peripheralManager(_:didReceiveWriteRequests:)`.
* If Android writes a payload that exceeds the MTU, CoreBluetooth splits it into multiple write chunks. 
* macOS must check the `offset` parameter of `CBATTRequest`. If `offset` is greater than 0, macOS should append the request's data to a buffer. When the final chunk is received (e.g. standard UTF-8 string is fully parsed or delimited), macOS processes the assembled buffer.

## 4. Cryptographic Operations (Swift / CryptoKit)

macOS must implement Curve25519 (ECDH) key agreement and HMAC-SHA256 session proofs.

### Session Key Derivation:
```swift
import CryptoKit

// Derive session key
let localPrivateKey = Curve25519.KeyAgreement.PrivateKey()
let peerPublicKeyRaw = Data(base64Encoded: androidEphemeralPubKeyBase64)!
let peerPublicKey = try Curve25519.KeyAgreement.PublicKey(rawRepresentation: peerPublicKeyRaw)

let sharedSecret = try localPrivateKey.sharedSecretFromKeyAgreement(with: peerPublicKey)
let sessionKey = sharedSecret.hkdfDerivedSymmetricKey(
    using: SHA256.self,
    salt: Data(),
    sharedInfo: Data(),
    outputByteCount: 32
)
```

### Session Proof Generation:
macOS must compute the HMAC-SHA256 session proof verifying ownership of the session key over the random 16-byte challenge generated by macOS:

```swift
import CryptoKit

let macChallenge = SymmetricKey(size: .bits128) // 16 bytes random
let challengeBytes = macChallenge.withUnsafeBytes { Data($0) }

// Compute HMAC-SHA256 using CryptoKit SymmetricKey sessionKey
let hmac = HMAC<SHA256>.authenticationCode(for: challengeBytes, using: sessionKey)
let macSessionProof = Data(hmac).base64EncodedString()
```

## 5. Peer Authentication Packet Response

Upon receiving the Android authentication challenge:
`auth:<androidChallengeBase64>:<androidSignatureBase64>:<androidPublicKeyEd25519>:<androidSessionProofBase64>:<androidIpAddress>`

macOS must:
1. Verify Android's Ed25519 signature on `androidChallenge` using `androidPublicKeyEd25519`.
2. Compute expected Android session proof: `HMAC-SHA256(sessionKey, androidChallenge)` and verify it matches `androidSessionProofBase64`.
3. If valid, macOS responds by notifying Android on the Notify Characteristic with:
   `auth_resp:<macChallengeBase64>:<macSignatureBase64>:<macSessionProofBase64>:<macIpAddress>`
   * Where `macIpAddress` is the macOS local network IP address (e.g. `192.168.1.150`).
4. Persist the Android `deviceId`, `name`, public key, and IP address to its secure local storage keychain.
